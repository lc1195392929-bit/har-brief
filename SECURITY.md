# Security

This is an early-stage data-minimization utility, not a certified sanitizer.
Read [the privacy contract](docs/privacy.md) before processing sensitive captures.

Do not post a real HAR, access token, session cookie, customer record, private URL
or a report containing sensitive metadata in an issue. Reproduce with a completely
synthetic capture. For a defect that cannot be described safely in public, use
GitHub's private vulnerability reporting if enabled; otherwise ask for a private
contact route without disclosing exploit details or data.

No service-level response time or dedicated security team is promised. Prefer the
latest reviewed source and retain the original capture privately. A passing test
suite is not proof that a report is appropriate for public disclosure.
